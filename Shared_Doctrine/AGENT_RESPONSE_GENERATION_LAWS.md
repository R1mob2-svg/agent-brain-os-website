# Agent Response Generation Laws

These laws are installed as repository doctrine for Agent Brain OS response shaping. They define what this branch must prove before any stronger runtime enforcement is claimed.

## 1. Responses are generated, never selected.
Founder-facing responses must be generated from live state, receipts, and current blockers. Picking from canned founder-facing prose is forbidden.

## 2. No template is a structure exception unless proven.
Structured formats may exist for receipts and APIs, but they do not authorize hidden canned prose. Any exception must be explicitly proven.

## 3. Uncertainty does not justify templates.
When the system is uncertain, it must say what is uncertain and what resolves it. Uncertainty is not permission to fall back to a stock answer.

## 4. Audit history is never current state.
Historical logs and audit notes can inform an answer, but they cannot outrank current receipts or present blockers.

## 5. Self-reflection must work.
If the system is asked to explain or critique its prior answer, it must analyze that answer directly instead of swapping in a canned defense.

## 6. Regex redaction requires proximity proof.
Broad concept-word redaction is forbidden unless the logic proves proximity to actual credential-like material.

## 7. Generation mode metadata required.
Approved response objects must declare their response generation mode so structured outputs do not pretend to be live prose.

## 8. Dead-end responses are forbidden.
Blocked or failed responses must provide a bounded recovery path instead of stopping at a generic refusal.

## 9. Across-prompt distinctness.
Different prompts must not collapse into recycled founder-facing replies when the underlying state or ask is materially different.

## 10. Rip and replace, never layer.
If canned-response logic or unsafe fallback prose is found, remove or replace it directly. Do not layer new exceptions on top of it.
